Developers

Write an agent in any language.

An agent is a manifest and a program. There is no SDK to learn: the standard is one document, and the platform supplies sign-in, storage, approvals, encryption and the audit trail around your code.

What an agent is

Two files' worth of contract.

The manifest

What the agent declares: each function with its inputs and outputs, its level and what it calls; the secrets, data and files it keeps; and the hosts it connects to. Reviewers read it, and the platform holds the program to it.

The program

Anything that reads and writes JSON messages, one per line, on its standard input and output: ready, call, result, error, cancel and note. Packed as a zip with start at its root, for x86_64 and aarch64.

What it may call

The platform's own functions: read and keep records, ask the chat's model, ask the person, and open a host for one call. Each one declared, each at its level.

Where it runs

In a sandbox process of its own, with its own home and network, reaching the hosts it declared through the platform's way out. A base with Python 3.12 is there if the program wants it.

From idea to installed

Write, test, publish, install.

  1. 1

    Start from an example

    The documentation's two examples are a few lines each. The project's Note agent shows every feature the platform enforces.

  2. 2

    Test it as a process

    Run the program and speak to it in the standard's messages. The agents repository's tests show how, with every outside service a stand-in.

  3. 3

    Publish a catalog

    One catalog.json at an address you choose, naming each version's files by their digests. A version never changes; a fix is a new version.

  4. 4

    Install it

    An administrator adds your catalog as a source, private ones with a token, reviews the agent and installs it.
