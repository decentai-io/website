What DecentAI is

A platform for running AI agents under your control.

It ships with no agents. You add the ones you need.

Ships empty

On day one the platform has users, groups and an audit log, and no agents. Nothing can act until you install something.

Every agent is built to one standard

Before it runs, an agent declares what it does, the resources it needs, the credentials it will use, and the permission level of each action.

Installed and uninstalled like an app

An administrator reads the declaration and installs one exact version. Uninstalling removes it completely. A new version is a new install.

Governed by what it declared

The platform holds every agent to its declaration on every action. Secrets are defined up front; an agent is given only the ones it declared, at the moment of an action, and every use is logged.

Custom agents for your own use cases

The same standard makes an agent for your ERP, portal or internal system a small job for any developer, with the platform's controls already in place.

Where the power is

Any capability can be added, and none exists that you did not install.

What agents do

Each agent does one kind of work, in the systems you already use.

You ask in plain language; the agent does the work and shows what it did.

Services you sign in to

Mail, calendars, chat, files, spreadsheets and forms in suites such as Microsoft 365 and Google Workspace. Read on a person's behalf, changed only on their approval.

Documents handed over

Contracts, invoices, applications, scans. Read, checked, turned into records, with a reference to where each fact came from.

Records you keep

Structured data an agent maintains for you: claims, requests, cases. Kept by the platform, searchable, exportable, owned by you.

Your own systems

ERP, CRM, case management, internal portals. Reached by agents built for them under the same standard.

Work that repeats

Watch this inbox, review this every Monday, chase what nobody answered. Runs on schedule, reports only when there is something to say.

Actions that matter wait for a person

Sending, booking, submitting, deleting: the agent shows the exact action and waits for approval.

One place to ask, any number of agents behind it, each doing the work it was installed to do.

What you control

Every control is set before an agent runs.

Enforced by the platform on every action. Nothing depends on the agent behaving well.

Which agents exist

An administrator installs one exact version after reading its declaration. Uninstall removes it. Nothing updates itself.

Who may use each agent

Agents are assigned to people and groups, and the assignment can be narrowed: one shared mailbox and no other, for example.

What each action is allowed to do

Every action carries a permission level, from read-only to changing the outside world. Actions above the level a user is trusted with wait for a person's approval.

Credentials and secrets

Declared up front, stored encrypted, never shown to a person or to the AI model. A secret is released only to the agent that declared it, when it acts, and every use is logged. For a connected account the agent gets a short-lived access token, never the password or the token that renews access. Any credential can be revoked at once.

The audit log

Every action, every approval, every credential used, by user and by time. Written by the platform, not by the agent, and it cannot be edited.

What your security team reviews

A declaration and a log, not a model.

Agents for your own systems

The systems only you have get their own agents.

The ERP, the CRM, the case system or the internal portal: built to the same standard and installed through the same door.

One standard, published

An agent is Python code you write, plus a declaration. You, your developers or anyone you choose write it against a stable interface, from a template. If it can be done in Python, an agent can do it.

The platform supplies everything around it

Sign-in and credentials, storage for the records it keeps, sharing, approvals, encryption and the audit log. The agent contains only the work itself.

Days, not a project

No database design, no admin screens, no integration layer to build. Declare what the agent keeps and needs, and the platform provides it.

Tested before it runs

Every agent ships with tests that run against stand-ins, so it is proven before it touches a real system.

Your own agents are yours. They are installed, governed and logged exactly like every other agent, and they never leave your environment.

Where it runs, and what stays yours

DecentAI runs inside your environment.

Nothing about your people, your conversations or your data passes through us.

Your environment

On your own computer, or in your own cloud account. There is no hosted version: the platform runs where you run it. One installation can serve several organizations, each fully separated from the others.

Your AI model

You choose the model provider and hold the keys. It can be changed per organization, and a model you host yourself is supported. The model sees a conversation; it never sees a credential.

Your data

Conversations, documents, records, credentials and the audit log stay in your environment. Everything an agent keeps for you can be opened and exported by you without the agent.

Open source

DecentAI is free software under the Apache-2.0 licence: read it, run it, change it. An update is installed when you choose to, and agent updates go through your own install approval.

Only two things ever leave your environment: the request to the AI model you chose, and what an agent does in an account you connected.

How to start

On your own computer, in minutes.

  1. 1

    Install it

    Download the app for Windows or a Mac and install it. It uses Docker or Podman and sets DecentAI up on this computer, reachable from this computer only.

  2. 2

    Add a model and agents

    Paste a key for the AI model you choose, add an agent source, and approve each agent after reading what it declares.

  3. 3

    Ask for the work

    Open a chat and ask in plain language. Actions that change things wait for your approval, and every one is in the audit log.
